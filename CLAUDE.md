# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

BIST Tracker: SaaS MVP that scans Borsa Istanbul stocks with admin-defined technical rules and produces a deterministic "Algoritmik Güven Skoru" (0–100, two-decimal weighted sum) plus notifications. It must never present itself as investment advice or place trades; the legal disclaimer must stay on every page footer and the auth screens. UI text is Turkish; code, comments and commit messages are English. Frontend routes are Turkish (`/ana-sayfa`, `/giris`, `/sifremi-unuttum`, `/sifre-sifirla`, `/eposta-dogrula`, `/kullanici/[slug]`, `/detay/[symbol]`, `/admin`, `/admin/giris`). The product name is not final: use `BRAND` from `frontend/src/lib/brand.ts` (backend: `PROJECT_NAME`), never a hard-coded name.

Product spec (Turkish): `bist_tracker.md` and `CURSOR.md` (both git-ignored, local only). Cursor rules in `.cursor/rules/*.mdc` contain older context; parts are stale (e.g. "JWT auth yok" — auth now exists).

## Running locally

```bash
docker compose up -d                       # Postgres 15 + Redis 7 (linux/arm64), repo root
cd backend && source venv/bin/activate
uvicorn app.main:app --reload --port 8000  # starts APScheduler too (lifespan)
alembic upgrade head                       # apply migrations
alembic revision --autogenerate -m "..."   # after model changes
cd frontend && npm run dev                 # http://localhost:3000
npm run lint / npm run build               # frontend checks
```

Backend unit tests: `cd backend && python -m pytest tests` (auth/TOTP/schemas, market data helpers). Scripts: `python -m app.scripts.verify_prices` (displayed prices vs official closes, needs the API running) and `python -m app.scripts.backtest_primary_filter` (walk-forward backtest of the primary filter, `--set key=value` to try parameters, `--out` to keep runs side by side; data cached in `backend/.cache/backtest/`). The frontend has no tests. Backend config comes from `backend/.env` via `app/core/config.py` (template `backend/.env.example`; `SECRET_KEY` is required). Frontend API base: `NEXT_PUBLIC_API_URL` or `http://127.0.0.1:8000/api/v1`.

The backend is run with the system Python 3.13 (`/Library/Frameworks/Python.framework/...`); `backend/venv` was created at an old path and lacks some packages. Yahoo Finance rate-limits aggressively (HTTP 429) — route new Yahoo calls through `gateway.call`, never call yfinance directly, and avoid scripts that rescan the whole universe repeatedly. With `uvicorn --reload`, every backend edit restarts the scan; the Redis L2 candle cache makes that cheap.

`frontend/` uses Next.js 16 / React 19 / Tailwind 4 — see `frontend/AGENTS.md`: read `frontend/node_modules/next/dist/docs/` before relying on remembered Next.js APIs.

## Backend architecture (`backend/app`)

- Routers are thin; logic lives in `services/`. All routers mount under `/api/v1` in `main.py`.
- **Auth**: PyJWT + bcrypt (`core/security.py`). Every JWT has a `token_type`; session tokens also carry `ver` (must equal `users.token_version`, bump it to revoke all sessions) and `adm`. Users must verify their e-mail before login; password reset links are single-use via a password-hash fingerprint (no token table). Admins sign in at `/auth/admin/login` → `/auth/admin/totp` (TOTP 2FA, `core/totp.py`, enrolment on first sign-in); only those sessions get `adm=true`, and `get_current_admin` requires it. Admins can invite people (`POST /admin/users`): the account is created verified with a random password and the invitee sets one from a 72 h link; system alerts go only to active, verified users. Auth endpoints are rate limited on Redis (`core/rate_limit.py`). Lost authenticator: `python -m app.scripts.reset_admin_2fa <email>` or another admin's "2FA sıfırla". Every mutating rule/universe/admin endpoint requires admin; `GET /rules` requires login; market read endpoints are public.
- **Data** (scans the whole BIST, ~620 symbols, within Yahoo's rate limit): every Yahoo call goes through `providers/yahoo_gateway.py` (token bucket `YAHOO_MAX_RPS`, concurrency cap, circuit breaker on 429, background lane so scans never block interactive requests). **Prices** come only from the batch quote snapshot `providers/quotes.py` (`quote_book`, one call per ~150 symbols): ticker, macro, overview, detail and the chart's last candle all use it. **Candles** (`providers/yfinance_provider.py`): per-symbol master frames in memory + Redis L2 (`candles_v1:*`, survives restarts); deep bootstrap once, then incremental 5-day deltas; one delta of the finest intraday interval is resampled into 15m/1h; 4h is resampled from 1h into BIST session bars like TradingView (10:00, 14:00, 18:00 closing auction; `FOUR_HOUR_SESSION_SPLITS`); masters stay fresh until the next session when the market is closed. `auto_adjust=False` (split- but not dividend-adjusted, matches official closes); past sessions' last intraday bar is reconciled with the official daily close (closing auction), and the live quote is overlaid on the last bar. Symbols are bare BIST tickers (`THYAO`); `.IS` is added inside the providers. Price history is never stored in Postgres.
- **Stock catalog vs universe**: `core/stock_catalog.py` is the generated symbol→name catalog of all traded BIST stocks (`python -m app.scripts.sync_stock_catalog [--activate-all]`; curated names are kept). `universe_stocks` table is the actively scanned subset (currently all), edited in the admin panel.
- **Rule engine** (`services/rule_engine.py`): a `Rule` = `indicator_1(+params)` `condition` against `static_value` or `indicator_2(+params)`, on its own `timeframe`, adding `score_impact` when met. RSI_TRENDLINE is a descending resistance line from the main RSI peak T1 through a later reaction high T2; `RuleEngine.trendline_signal` (shared with the backtest) accepts only a fresh, confirmed breakout where RSI itself rose through the line in the bottom region, never a steep line sliding under a flat RSI; optional early `near` stage (RSI rising just under the line), minimum line steepness and RSI-dip checks (`TRENDLINE_DEFAULTS` holds every parameter; rules override them in `indicator_2_params`). The result is exposed as `peak_qualifies`, `stage` and per-check `trend_checks`; an upward RSI_TRENDLINE rule is met exactly when the signal is valid. Second step of the primary filter (`confirm_ma_days`/`confirm_window_sessions` in the same params, `market_service.apply_primary_confirmation`): the RSI signal arms the stock in Redis, and it passes once price is above the N-day average of 5m bars (`RuleEngine.session_sma`) within the window; `primary_rsi_passed` keeps the RSI stage. One rule is the `is_primary_filter` (enforced unique in the rules router). Rule input is validated in `schemas/rule.py`.
- **Market service** (`services/market_service.py`): scores are always computed on canonical candle sets (`EVALUATION_PERIODS`), never on the chart period the user picked, so overview and detail agree. `get_overview` is stale-while-revalidate: it returns the last snapshot (memory → Redis, kept 24h) and refreshes in the background (single flight); before any snapshot exists it returns `status: "warming"` with partial results (most liquid first). Evaluations are memoised per symbol on (rules, candle versions, quote) and run in worker threads. `public_overview` strips `rules_breakdown` (alerts need it server-side) and re-stamps prices from the quote book. Rule or universe changes must call `invalidate_market_caches()`. Admin `/admin/stats` exposes `data_pipeline` metrics.
- **Notifications**: the APScheduler job (`scheduler/main.py` → `services/task_runner.run_market_scan`) refreshes the overview every `SCAN_INTERVAL_MINUTES` and calls `services/alert_dispatcher.dispatch_alerts` (system alerts for primary-filter passes + users' custom alerts), only during BIST hours (`core/market_hours.py`, `NOTIFY_ONLY_WHEN_MARKET_OPEN`). Page visits never trigger notifications. `NotificationService` de-duplicates via Redis cooldowns keyed by user/symbol/rule.
- Default rule suite for the admin "seed" button: `core/default_rules.py`.

## Frontend architecture (`frontend/src`)

- All HTTP goes through `services/api.ts` (no raw `fetch` in pages/components): it attaches the access token and on 401 does a single shared silent refresh (`refreshSession`); if that fails it clears the session and fires a `session-expired` event that `components/auth/SessionGuard.tsx` turns into the re-login modal. Session storage helpers are in `lib/auth.ts` (`isAdminAccount` = role, `isAdminSession` = 2FA-scoped session required by `/admin`). Auth screens share `components/auth/AuthShell.tsx` and `components/auth/fields.tsx`. Keep `services/api.ts` / `types/index.ts` aligned with backend payloads.
- The dashboard (`app/ana-sayfa/page.tsx`) keeps state and data fetching; its UI lives in `components/dashboard/` (header, market pulse, symbol lists, instrument panel, ranked lists, rule drawer). `?sembol=XXX` opens it with a stock selected. The stock detail page reuses these parts plus `components/detail/DetailBlocks.tsx`. The admin console (`app/admin/page.tsx`) holds data and handlers; sections live in `components/admin/` (shell with `#kurallar/#kullanicilar/#evren` hash routing, toast/confirm via `components/ui/feedback.tsx`). The profile page (`app/kullanici/[slug]/page.tsx`, tabs `#alarmlar/#bildirimler/#hesap`) follows the same split with `components/profile/`; account self-service uses `PATCH /auth/me`, `/auth/change-password` (returns fresh tokens, revokes other sessions), `/auth/logout-all` and `/auth/delete-account` (non-admins only, FK cascades remove user data). Relative/absolute date helpers live in `lib/time.ts`.
- Rule breakdown rows are rendered by `components/rules/RuleConditionText.tsx` (shared by dashboard drawer and detail page).
- Charts use `lightweight-charts` (`components/charts/ChartWrapper.tsx`), including the RSI pane and trendline overlay.
- Dark trading theme (`#0b0e14` background, slate text, blue accent); reuse existing shadcn/ui components rather than adding new palettes.
